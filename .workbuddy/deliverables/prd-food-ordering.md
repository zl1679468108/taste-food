## 1. 产品概述

### 产品名称
**小店点餐**（暂定名，可自定义）

### 产品定位
一款面向小微餐饮商家的扫码点餐微信小程序，顾客通过扫描桌码即可完成浏览菜单、下单、支付全流程。

### 目标用户
- **核心用户（商家）**：个体餐饮经营者，有小本生意（奶茶店、小吃店、快餐店），想降低人工点餐成本、提升翻台率
- **使用用户（顾客）**：到店消费或外卖点餐的普通消费者

### 核心价值一句话
**让小微餐饮商家零成本实现扫码点餐，顾客自助下单省心省力。**

## 4. 订单流转图

### 订单生命周期

```
┌──────────┐     商家接单     ┌──────────┐
│  待支付   │ ──────────────→ │  已支付   │
│ (待支付)  │      (模拟)      │ (待接单)  │
└──────────┘                 └──────────┘
                                    │
                              商家点击"接单"
                                    ↓
                              ┌──────────┐
                              │  制作中   │
                              │ (制作中)  │
                              └──────────┘
                                    │
                              商家点击"完成"
                                    ↓
                    ┌─────────────────────────┐
                    │       到店              │ 外卖
                    ↓                         ↓
              ┌──────────┐            ┌──────────────┐
              │  待取餐   │            │  配送中/已完成 │
              │ (可取餐)  │            │  (配送中/已送达)│
              └──────────┘            └──────────────┘
```

### 状态枚举

| 状态值 | 含义 | 说明 |
|:------|:----|:----|
| `pending_payment` | 待支付 | 订单已创建，待模拟支付 |
| `paid` | 已支付/待接单 | 支付成功，等待商家确认 |
| `preparing` | 制作中 | 商家已接单，正在制作 |
| `ready` | 待取餐（到店） | 制作完成，等待顾客取餐 |
| `delivering` | 配送中（外卖） | 外卖已发出，配送中 |
| `completed` | 已完成 | 顾客已取餐/已送达 |
| `cancelled` | 已取消 | 订单被取消 |

## 5. 支付沙箱方案

### 设计思路

当前阶段 **不接入真实微信支付**，使用模拟支付页面替代。后续接入真实支付时，只需替换支付模块，不涉及订单逻辑改动。

### 交互流程

1. 用户提交订单 → 跳转到 `/pages/payment/payment` 页面
2. 页面显示：订单金额、订单编号、"确认支付"按钮
3. 点击"确认支付"：
   - 调用云函数 `sandboxPay`（更新订单状态为 `paid`）
   - 页面跳转到支付成功页（展示成功动画 + 预计取餐/送达时间）
4. 点击"取消支付"：
   - 订单状态保持 `pending_payment`
   - 返回订单详情页，可再次发起支付

### 数据字段

订单中新增 `payStatus` 字段：

```json
{
  "payStatus": "pending" | "paid"
}
```

### 后续真实支付接入

仅需：
1. 创建 `payment/payment` 页面下的真实微信支付调用（`wx.requestPayment`）
2. 云函数中调用微信支付统一下单 API 获取 prepay_id
3. 支付结果回调后更新 `payStatus`
4. 页面 UI 无需变更

## 6. 数据模型

### 商品表（`goods`）

| 字段 | 类型 | 说明 |
|:----|:----|:----|
| `_id` | string | 自动生成 |
| `name` | string | 商品名称 |
| `price` | number | 价格（单位：分，即 1000 = 10 元） |
| `categoryId` | string | 所属分类 ID |
| `image` | string | 商品图片云存储 URL |
| `specs` | array | 规格选项，如 `[{name:"冰度", options:["少冰","去冰"]}]` |
| `description` | string | 商品描述 |
| `soldCount` | number | 已售数量 |
| `isAvailable` | boolean | 是否上架 |
| `createdAt` | date | 创建时间 |

### 分类表（`categories`）

| 字段 | 类型 | 说明 |
|:----|:----|:----|
| `_id` | string | 自动生成 |
| `name` | string | 分类名称（如"饮品"、"小食"） |
| `sort` | number | 排序序号（小→大排序） |
| `icon` | string | 分类图标（可选） |

### 订单表（`orders`）

| 字段 | 类型 | 说明 |
|:----|:----|:----|
| `_id` | string | 自动生成 |
| `orderNo` | string | 订单号（如：`202606150001`，日期+3位序号） |
| `items` | array | 商品列表（见订单商品子表） |
| `totalPrice` | number | 总价（单位：分） |
| `status` | string | 订单状态（见第4节） |
| `payStatus` | string | 支付状态：`pending` / `paid` |
| `orderType` | string | 订单类型：`dine_in` / `delivery` |
| `tableNo` | string | 桌号（到店订单） |
| `deliveryInfo` | object | 配送信息（外卖订单）：`{address, phone, name, note}` |
| `remark` | string | 顾客备注 |
| `contactPhone` | string | 联系电话 |
| `createdAt` | date | 创建时间（自动记录） |
| `updatedAt` | date | 更新时间 |

### 订单商品子表（内嵌于订单表 `items` 字段）

| 字段 | 类型 | 说明 |
|:----|:----|:----|
| `goodsId` | string | 商品 ID |
| `name` | string | 商品名称（下单时快照） |
| `price` | number | 单价（单位：分） |
| `quantity` | number | 数量 |
| `specs` | array | 所选规格，如 `["少冰","五分糖"]` |

> **说明**：由于订单量不会很大，订单商品采用**内嵌数组**方式存储在订单表中，不需要额外建子表。这样查询订单时一次读取即可，减少云数据库请求次数。

## 7. 商家端方案

### 推荐方案：**小程序内嵌商家入口**

对于编程小白用户，推荐直接在同一个微信小程序中通过身份校验进入商家管理界面，而非开发独立的 Web 管理后台。

#### 理由

| 维度 | 小程序内嵌商家入口 | 独立 Web 管理后台 |
|:----|:------------------|:-----------------|
| **开发成本** | 低，复用现有 UI 组件和云函数 | 高，需额外开发 Web 端 + 部署 |
| **上手门槛** | 商家直接用微信打开即可管理，无需额外登录 | 需注册账号、记住网址、适合电脑操作 |
| **使用场景** | 手机随时随地查看订单、接单 | 需在电脑前操作 |
| **推送能力** | 可通过订阅消息 / 客服消息通知 | 需额外做推送对接 |
| **适合人群** | 个体小商家，没有固定办公桌 | 有电脑的连锁店 |

#### 具体设计

1. **入口**：小程序首页底部导航或右上角菜单 → "商家中心"
2. **身份校验**：简易的密码验证（首次设置密码），或微信 OpenID 白名单
3. **管理页面**：
   - 订单看板（默认页）：新订单置顶高亮 + 橙色角标
   - 订单列表：按状态 tab 切换（待接单 / 制作中 / 已完成）
   - 订单操作：接单按钮 → 开始制作按钮 → 完成按钮
   - 商品管理（P1 补充）：上架/下架商品、修改价格

#### 后期扩展

当商家规模变大、需要看数据报表时，可再开发 PC Web 管理后台。但初期完全用小程序内商家入口即可满足需求。

## 9. 待确认问题

以下事项需要你（老板）来拍板决定，开发前需要明确：

### 9.1 桌号管理
- 你店里有多少桌？桌号怎么编？（如 A01、A02…或 1、2、3…）
- 是否每张桌子印不同的二维码（推荐），还是同一码选桌号？
- > **建议方案**：每张桌子单独生成二维码（码中带桌号参数），顾客扫码自动识别桌号，无需手动选择。

### 9.2 外卖配送范围
- 外卖配送范围是多大？（附近 1 公里？2 公里？还是不限？）
- 超出范围的订单怎么处理？（不接受 / 加收配送费）

### 9.3 配送费
- 外配送费是多少？（固定 3 元？满多少免配送费？）
- 前期建议先用**固定金额**（如 3 元），后续再根据距离核算。

### 9.4 营业时间
- 你的店铺营业时间是什么？（如 10:00-22:00）
- 非营业时间是否允许顾客浏览菜单但不能下单？

### 9.5 商家账号权限
- 商家管理入口是否只你一个人用？是否需要给店员开子账号？
- 前期建议就你一个人管理，后续需要再扩展。

### 9.6 商品数据
- 你有现成的菜单和价格表吗？建议整理一份 Excel 给开发，直接导入。
- 商品图片是否需要现拍或网上找素材？

### 9.7 是否已有微信小程序账号
- 是否已经注册了微信小程序账号（AppID）？
- 如果还没有，需要先注册（个人或个体工商户主体均可）。
- 云开发环境是否已经开通？
