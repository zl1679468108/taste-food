## 2. 产品定义

### 2.1 产品目标

1. **最小可用闭环**：实现从"扫码→浏览菜单→加购→下单→支付→商家接单→出餐"的完整交易闭环，让一家烧烤摊能零成本跑通线上点餐流程。
2. **门店运营提效**：商家端提供订单实时推送、按状态分组管理、今日营收看板，降低漏单/错单率，提升出餐效率。
3. **多角色体验分离**：顾客端聚焦"快选快下单"，商家端聚焦"接单管单"，两端互不干扰，为未来 SaaS 多租户架构打好数据基础。

### 2.2 用户故事

#### 顾客（Customer）

| ID | 用户故事 |
|----|----------|
| US-01 | 作为一名顾客，我想要扫码后看到按分类排列的菜单，以便快速找到想吃的烧烤菜品。 |
| US-02 | 作为一名顾客，我想要选择菜品的规格（口味/份量），以便商家按我的要求制作。 |
| US-03 | 作为一名顾客，我想要使用购物车管理已选菜品，以便在下单前统一确认。 |
| US-04 | 作为一名顾客，我想要选择配送方式（外卖/自取/堂食），以便按我的用餐场景下单。 |
| US-05 | 作为一名顾客，我想要支付后实时查看订单状态，以便知道商家是否已接单、是否开始制作。 |

#### 商家（Admin）

| ID | 用户故事 |
|----|----------|
| US-06 | 作为一名商家管理员，我想要在新订单到来时收到实时通知，以便第一时间接单制作。 |
| US-07 | 作为一名商家管理员，我想要按状态（待接单/制作中/配送中/已完成）筛选订单，以便高效管理出餐流程。 |
| US-08 | 作为一名商家管理员，我想要快速上架/下架菜品和管理分类，以便灵活调整菜单。 |
| US-09 | 作为一名商家管理员，我想要查看今日营收概览，以便快速掌握当日经营状况。 |

## 4. 待确认问题

以下是需要团队进一步讨论确认的开放问题：

1. **身份认证流程**：顾客扫码后是否需要微信授权登录？还是先以游客身份购物，下单时再要求授权？
   - 倾向方案：扫码进入后以游客模式浏览菜单，下单时触发微信授权获取 openid

2. **购物车持久化**：购物车数据存前端 Zustand（刷新丢失）还是同步到 Supabase？
   - 建议 MVP 阶段存前端 Zustand，后续视需要同步到后端

3. **商家端入口**：商家管理员如何登录？是独立小程序管理后台，还是在顾客小程序内通过角色切换进入？
   - 建议方案：商家使用同一小程序，通过「商家入口」按钮跳转至管理界面，登录验证身份

4. **地址管理**：MVP 阶段用户地址如何获取？
   - 方案 A：用户手动输入
   - 方案 B：调用微信小程序「获取收货地址」API
   - 倾向方案 B（用户体验更佳）

5. **堂食场景桌号**：堂食模式下，桌号由顾客输入还是由商家扫码带入？
   - 倾向方案：商家在每张桌上贴带桌号参数的二维码，扫码时自动带入 table_no

6. **拒绝订单流程**：商家拒绝订单后，是否允许顾客重新选择其他商家（当前单店模式无此场景）？
   - 建议：拒绝即取消，顾客端显示「商家已拒绝，请联系商家」
